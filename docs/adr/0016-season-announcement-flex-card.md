# 季公告改成「一段純文字＋數張 Flex 卡」

`@Dobby season <季度>` 原本把 Notion `NEW_SEASON` 模板轉成純文字，用手打的 `————————` 切成最多 5 則 text，管理員複製、潤飾後貼到群組。2026-10-01 使用者決定不再潤飾，直接轉傳 bot 的回覆，所以改成跟公告卡（[ADR 0015](0015-news-flex-card.md)）同風格的卡片，由 `src/commands/season-card.ts` 的 `buildSeasonBubble()` 組裝。以下記錄幾個取捨。

**含 `{NEW_SEASON_NEWS}` 的段落回純文字，其他段落回卡片。** 第一段是 `NEWS_TEMPLATE` 的內容，管理員要貼進 LINE 記事本，記事本只能貼文字，卡片的文字又不能複製，所以這段必須是純文字。判斷規則看「段落裡有沒有這個變數」，不寫死「第一段」，管理員調整段落順序時不用改程式。

**切段改看區塊，不看文字。** 舊版先把整頁轉成文字再用 `————————` 切。卡片要用 Notion 的標題（heading）分小標、讀表格，所以要保留區塊結構，改成「內容剛好是 `————————` 的段落區塊」才切（`splitByDivider()`）。代價是 `————————` 跟其他文字擠在同一個段落（Notion 裡 Shift+Enter 換行）時不會切，那段的卡片會直接出現那串 `—`。現在的模板每條分隔線都是獨立段落，文件也寫明要這樣打。段落裡有 `————————` 但不只有它時，`isDividerBlock()` 會記一筆 warn，管理員發現卡片少了可以到 `/logs` 查原因。每段內的「先切段再代入」跟公告卡一樣，避免 `{PLAY_DATES}` 這種多行變數被誤認成段落邊界。

**卡片標題取該段第一行。** 模板每段開頭都是一行沒有小標的文字（「中華科大 - {SEASON_TITLE}」、「{SEASON_SHORT} 費用說明」），剛好當卡片標題，不用另外在程式裡寫死標題。那一行底下如果還有文字，留在內文第一段。段落一開頭就是 Notion 標題或表格時沒有這一行，改用 `formatSeasonTitle()` 的季度當標題。標題區沒有左上角小字，因為標題本身已經有季度，再放會重複。所有卡片都用螢光綠擴音器徽章（沿用公告卡的 `megaphone-dark.png`），不依段落換圖示，因為程式不知道每段在講什麼，也不必為此多做圖示。

**表格的版面看欄名，不看位置。** 2026-10-01 使用者把兩張卡片的內容改成 Notion 表格，看過 mockup（https://claude.ai/artifact/88WHEHW8c8V8htGL3wjSSe ，三個方向：數據格、明細表、螢光大數字）後，場地資訊選數據格、費用說明選螢光大數字。版面要讓管理員能在 Notion 自己調，所以規則都寫在表格裡：有 `column` 欄的套數據格，`wide` 佔滿一列、其他兩兩一列；有 `highlight_title` 欄的套螢光大數字，`true` 的列突顯。不用「第幾張卡片用哪種版面」，因為那樣管理員調整段落順序就會套錯；也不寫死「續打是重點」，突顯哪幾列由 `highlight_title` 決定。落單的格子佔半格而不是撐滿，同一張卡的格子寬度才一致。欄名用 `readHeaderTable()`（`blocks-to-text.ts`）依標題列對應，管理員可以調整欄位順序或多加欄位。兩種欄都沒有的表格不丟掉，每列串成一行當一般文字，並記一筆 warn，而且就算它在段首也不拿來當卡片標題（否則標題會變成「續打 $2200 @… true」這種整列文字）；只有標題列、或每列都被略過的表格整塊不畫，同樣記 warn。`blocksToText()` 本身不輸出表格，不處理的話表格內容會整個消失。altText 和純文字 fallback 改用 `seasonCardToText()` 從卡片內容產生，不用 `blocksToText()`，原因相同。

**大數字的前後綴用 span。** 數據格的「內容前綴／內容／內容後綴」是同一行的三段 span（小字灰／大字粗體／小字灰），空的 span 不放，因為 Flex 的 text 和 span 都不能是空字串。

**底部沒有操作按鈕，只有付款列的「複製」。** 卡片是要轉傳到群組的季度資訊，不是要大家操作的東西，所以不放公告卡那種「付款資訊／指令清單」按鈕。付款區塊（見下方）的「複製」是例外：Flex 卡片不能長按複製文字，帳號只能靠按鈕複製，理由跟付款卡相同（[ADR 0014](0014-payment-flex-card.md)）。clipboard action 要 LINE 14.0.0 以上，季公告卡會轉傳給全群組，碰到舊版 LINE 的機會比 `@Dobby 付款` 多，真機測試項目有列。

**`{NEW_SEASON_NEWS}` 用指令指定的季，不用今天所在的季。** `@Dobby 公告` 一律用 `getCurrentSeasonName()`，但季公告通常在季末產生下一季的，例如 12 月下 `season 2027Q1`，用當季就會拿到 Q4 的人數和日期。所以 `news.ts` 抽出 `renderNews()`，季度由呼叫端傳入。季公告已經為了 mention 名單查過指定季和上一季所有成員的人員資料，`{LIST_ALL_PEOPLE}` 直接從裡面挑指定季的成員，不再查一次（兩季成員本來就由 `peopleRepo.findMembersOfSeasons()` 用一次 query 一起查回）。`NEWS_TEMPLATE` 的變數在 `renderNews()` 裡先代入完，結果再當成 `{NEW_SEASON_NEWS}` 的值；`applyPlaceholders()` 是單次 `replace`，代入的值不會再被掃一次，所以兩套變數不會互相干擾。

**金額欄位缺值時報錯，不代入 0。** `{REAL_PRICE}`（指定季的 `每人實際收費`）、`{REFUND_PRICE}`、`{BALANCE}`（上一季的 `季打退費`、`結餘`）都是管理員手填的，上一季的兩欄要等那一季結束才會填。退費當 0 算，續打費會變成全額，仍是一個看起來合理的數字，管理員轉傳出去才會被發現，所以任一欄沒填就回一則訊息列出缺哪幾欄，不產生公告。Notion 欄位被改名或改成非 number 型別時，`getNumber()` 一樣回 null，bot 也會說「還沒填」；看到這句但 Notion 上明明有填，先檢查欄位名稱和型別。`@Dobby 公告` 的 `{PRICE_PER_PERSON_FOR_SEASON}`（也改讀 `每人實際收費`）缺值時則代入提示文字：那是給全體成員看的常用指令，一個欄位沒填不該讓整則公告失敗，做法跟 `{PAYMENT_V2}` 讀不到時一樣。

`{NEW_SEASON_NEWS}` 代入後是空的（`NEWS_TEMPLATE` 被清空）時也回錯誤，不讓要貼記事本的那則默默消失。反過來，`{PAYMENT_V2}` 讀取失敗時的降級提示（「付款資訊讀取失敗…」）會原樣出現在這段文字裡，貼之前要看一下。

**卡片裡的付款區塊沿用付款卡的列。** 2026-10-02 使用者在費用說明那段最後加了一個只有 `{PAYMENT_V2}` 的段落，要放「跟付款卡相同的資訊」。mockup 比較過「付款卡原樣」和「精簡」（帳號放大、沒帳號的兩兩並排），使用者選原樣，所以直接共用 `payment-card.ts` 的 `paymentMethodRow()`，付款卡改樣子這裡會一起變。只有「整個段落就是 `{PAYMENT_V2}`」才畫成付款列，夾在句子裡的照一般變數代入成純文字，跟分隔線、`{NEW_SEASON_NEWS}` 的判斷方式一致。`PAYMENT_V2` 讀一次（`news.ts` 的 `loadPaymentPage()`），`{NEW_SEASON_NEWS}` 裡的付款段落和卡片共用，不會兩邊讀到不同時間點的資料。讀不到或表格讀不懂時，「付款方式」底下放跟 `@Dobby 公告` 相同的純文字或提示句，不讓整張卡失敗，理由同 ADR 0014：付款是次要段落。季公告的變數 regex 也從 `[A-Z_]+` 改成 `[A-Z0-9_]+`，否則 `{PAYMENT_V2}` 比對不到。

**`{PAYMENT_INFO}` 拿掉。** 模板已經不用它，付款資訊改由 `{NEW_SEASON_NEWS}` 提供。舊的 `PAYMENT` 頁面因此沒有程式在讀，付款資訊只剩 `PAYMENT_V2` 一份（[ADR 0014](0014-payment-flex-card.md)）。

**卡片太大或只有標題時，那段改回純文字。** 跟公告卡一樣用 `fitsBubbleSizeLimit()` 檢查 30KB 上限。只有一行標題、沒有內文的段落畫成卡片會只剩照片標題區，也改回純文字。純文字用 `splitIntoTextMessages()` 依 5000 字切。全部訊息加起來超過 LINE 單次回覆的 5 則時，回一則錯誤訊息，不送出會被 LINE 退回的請求。2026-10-01 用改成表格後的正式模板產生 `2026Q4` 的公告：純文字約 600 字，兩張卡分別約 5KB 和 6KB（第二張含付款區塊），LINE validate API 回 200。
