# 公告改用依 Notion 標題分段的 Flex 卡

`@Dobby 公告` 原本把 Notion「所有公告」的 `NEWS_TEMPLATE` 頁面轉成純文字（`blocksToText`）、代入當季變數後整段回覆。報名狀態卡、指令清單卡、名單卡、付款資訊卡都改成 Flex 後（[ADR 0010](0010-registration-status-flex-card.md)、[0012](0012-command-list-flex-card.md)、[0013](0013-name-list-flex-card.md)、[0014](0014-payment-flex-card.md)），公告也改成同風格的卡片，由 `src/commands/news-card.ts` 的 `buildNewsBubble()` 組裝。以下記錄幾個取捨。

**版面只認 Notion 的「標題」和「分隔線」，文字全部照管理員打的內容。** 公告很長，而且是管理員在 Notion 自由編輯的，改成卡片最大的風險是版面寫死在程式裡，管理員就不能只改 Notion。mockup 比較過三種做法：A 把整段文字原樣放進卡片，只加照片標題區；B 依 Notion 的標題切段，標題變灰色小標，段落之間畫細線；C 在 B 上面再加一排「季打每人／零打每次／地點／場地數」重點格，由程式排版。使用者選 B。A 看起來跟純文字差不多；C 的重點格跟 Notion 裡「季打費用」等段落內容重複，要管理員刪掉那幾段，這幾段的版面改由程式決定，管理員就不能再自己改。B 的規則管理員容易理解：新增一段就是在 Notion 加一個標題，刪段落、改字、調順序都不用動程式。

**分段規則（`blocksToSections()`，`src/services/notion/blocks-to-text.ts`）。** 最上層的 heading_1/2/3 開新的一段，標題文字當段落小標；最上層的分隔線結束目前這段，分隔線本身不輸出，因為卡片自己會在段落之間畫線。每段內文的轉換規則跟 `blocksToText` 一樣，包括項目符號、編號、待辦、保留中間的空行。可展開標題（toggleable heading）底下的內容就是該段內文。在卡片上這些內容不縮排；但 altText 和純文字 fallback 用的是整頁的 `blocksToText`，那裡會縮排 2 個空白。巢狀在 toggle 或欄位裡的標題不切段，照原本的縮排規則留在內文裡。第一個標題之前的內容會變成一段沒有小標的段落，不會被丟掉。標題和內文都空的段落會略過，例如分隔線後面緊接著標題。

**先切段，再代入變數。** `{LIST_ALL_DATES}` 這類變數的值本身有換行。如果先代入再切段，變數值的內容可能被誤認成段落邊界，所以 `news.ts` 先用區塊切好段落，再對每段的標題和內文各自代入。

**標題區的季度和副標題由程式產生，不從模板拿。** 左上角是「2026 Q4（10~12月）」，格式跟報名人卡一樣；副標題是「共 N 人・N 次」，資料來自季租紀錄。模板原本的第一行是 `{SEASON} {FROM_TO_MONTH}`，它在第一個標題之前，會變成一段沒有小標的段落，跟標題區的季度重複。2026-10-01 使用者已經從 Notion 刪掉這一行，程式不特別處理。代價是 altText 和純文字 fallback 改從「報名名單」開始，開頭沒有季度。

**底部兩顆按鈕：「付款資訊」（`@Dobby 付款`）和「指令清單」（`@Dobby 指令`）。** Flex 卡片不能長按複製文字，「付款資訊」會打開付款卡，帳號可以用卡上的複製按鈕複製（[ADR 0014](0014-payment-flex-card.md)）。沒有放「本季報名人」，因為公告本身就列出完整名單。也沒有放「+1 零打」，因為公告卡很長，滑動時容易誤觸，一按就直接報名當週零打。

**Flex 的 text 不能是空字串。** LINE 遇到空字串會整則退回，而 `reply-service.ts` 只記一筆 warn，群組裡什麼都看不到。所以只有空白的小標或內文不畫，兩者都空的段落整段略過。變數值是空的情況有兩種處理：`{PAYMENT_V2}` 讀不到時會代入一句提示（見 `loadPaymentText()`）；其他變數代入後就算整段變空，也只是少畫一段。代入變數後，如果沒有任何一段有字，例如模板只有空白段落和分隔線，或變數全部代入成空字串，就回純文字「公告內容為空」，不送一張只有標題區的卡片。

**卡片太大時改回純文字，並切成多則。** 單一 bubble 的 JSON 上限是 30KB。2026-10-01 用正式的 `NEWS_TEMPLATE` 組出來的卡片約 6KB，LINE validate API 回 200。超過上限時（`fitsBubbleSizeLimit()`，跟名單卡、付款卡共用）改送改版前的純文字。但卡片超過 30KB 時，文字通常也超過 LINE 單則 text 的 5000 字上限：中文一個字 3 bytes，加上每段的版面開銷，算下來不到 5000 字的公告很難把卡片撐過 30KB。所以 `splitIntoTextMessages()` 會依換行把文字切成多則，每則不超過 5000 字；單一行就超過 5000 字時直接硬切。一次 reply 最多 5 則，超過 5 則才把最後一則截斷，加上「…（公告太長，後面省略）」。正常的公告碰不到這個限制。

**altText 沿用改版前的純文字。** 通知、`/logs`、舊版 LINE 看到的就是原本那段公告，跟名單卡一樣用 `truncateAltText()` 截到 400 字。找不到 `NEWS_TEMPLATE`、找不到當季季租資料、系統錯誤這幾種情況，維持回純文字。

**`@Dobby season` 的季公告草稿維持純文字。** 草稿是給管理員複製後貼到群組記事本或公告用的，Flex 卡片不能複製文字，所以不改。
